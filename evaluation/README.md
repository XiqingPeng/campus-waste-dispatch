# 清运策略对照

比较固定巡检与事件触发调度。输入是宿舍区 A、B、C 三站的两组合成满桶事件。坐标与网页示意图一致，直线距离按每坐标单位 3 米换算。时间、距离和事件均为课程演示设定。

## 复现

在仓库根目录用 Python 3.8 或更新版本运行，无需安装依赖。

```bash
python3 evaluation/dispatch_compare.py
```

事件和常量在 [simulated_events.json](simulated_events.json)，结果存为 [results.csv](results.csv)。

## 对照条件

- 每次回放接收前 60 分钟的满桶事件。两种策略各用一名保洁员，出发和收工地点都为同一值班点。步速为 1 m/s，每桶清运耗时 2 分钟。
- **固定巡检**在第 0、20、40 分钟从值班点按 A → B → C 的顺序巡检，处理到达时已报满的桶，然后返回值班点。空桶检查的停留耗时设为零。保洁员忙碌时跳过该轮发车时刻。观察窗口结束后，仍有满桶时按相同间隔继续巡检。
- **按需清运**在保洁员空闲时派单。从最早报满时间起 60 秒内的待办视作同一优先级，优先选距当前位置最近的一桶。执行途中始终完成当前任务，再从当前站选择下一单。保洁员空闲时留在上次服务位置，观察窗口结束且待办处理完后回到值班点。
- **累计满桶等待**统计每个桶从报满到完成清运的时长之和，单位为桶·分钟。**步行距离**累计每段行程，包含巡检空站、往返以及观察窗口外处理积压的路程。两种策略均处理完全部事件后结束。

## 回放结果

| 合成事件 | 策略 | 累计满桶等待（桶·分钟） | 最长单桶等待（分钟） | 步行距离（米） |
| --- | --- | ---: | ---: | ---: |
| 稀疏，3 次报满 | 固定巡检 | 12.12 | 6.22 | 1713.94 |
| 稀疏，3 次报满 | 按需清运 | 12.22 | 4.53 | 571.31 |
| 高峰，12 次报满 | 固定巡检 | 76.47 | 15.53 | 2285.26 |
| 高峰，12 次报满 | 按需清运 | 120.83 | 16.42 | 2059.35 |

稀疏回放中，按需清运走得更少，累计等待接近固定巡检。高峰回放中，按需清运仍减少里程，但累计等待增加。例如第一次处理 A 站可回收桶后，A 站也有厨余桶待办。C 站的其他垃圾桶报满更早，超出了 60 秒的并列窗口，保洁员先到 C 站清运。在同一轮巡检中，固定策略到 B 站后连续清空了可回收桶和厨余桶。以上比较只覆盖给定事件、巡检节奏和路径，实际校园运营需要测量步行距离、清运时间和满桶分布。
